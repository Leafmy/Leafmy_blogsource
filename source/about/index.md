  - 木星画面的**校验基准**（仅用于离线比对，不随站点发布）：ESA/Hubble & NASA，OPAL 计划 2024-01-05 观测（[heic2404b](https://esahubble.org/images/heic2404b/)，CC BY 4.0）
  - 银河：ESO/S. Brunier，[The Milky Way panorama](https://www.eso.org/public/images/eso0932a/)（CC BY 4.0）
  - 金星/地球/火星/土星/天王星/海王星贴图：[Solar System Scope](https://www.solarsystemscope.com/textures/)（CC BY 4.0）
  - 水星与伽利略四卫贴图：USGS Astrogeology / NASA（MESSENGER、Galileo、Voyager 全球拼接产品，公有领域）
  - 恒星位置与亮度：Yale Bright Star Catalogue (BSC5) 数据（经 [d3-celestial](https://github.com/ofrohn/d3-celestial) 整理，BSD-3-Clause）
  - 说明：首页画面为**合成图**，这一点必须说清楚 ——
    - **主体**：首页是**木星系特写**（木星 + 木星环 + 伽利略四颗卫星），七颗远景行星默认不出现在画面里。
    - **位置与大小**（仅 `?planets=1` 切回"太阳系全家福"时）：各天体的画面次序按真实日心黄经、相对大小按真实角直径做幂次压缩（真实离角下水星/金星/地球/火星永远聚在太阳附近 ±11.5° 内，不可能同框），但**它们落在画面上的那条弧是构图**：形状由 `space-scene.css` 里的三个贝塞尔控制点决定，不表示真实的天球位置。
    - **亮度**：保留真实反照率差异，但各天体按不同曝光时间合成（曝光曲线写在 `space-system.js` 的 `IRRADIANCE_COMPRESS`，把 1/r² 的 3 万倍极差压到 ≈12:1），否则外行星在同一幅画面里不可见。这会让视觉星等的次序与真实排名不同。
    - **卫星**：Galileo 四颗卫星走的是**真实轨道**（真实半径/周期/共面，因此凌木、掩食、影凌都是几何的自然结果）。另有一颗**虚构的合成卫星**实现在代码里但**默认关闭**（`?fake=1` 可开）：在这个取景下不可能有真实卫星出现在木星盘面前方（真实卫星轨道半径都 ≥5.9 R_J，而出现在盘面前方要求 ≤1.39 R_J），所以它只能是构图元素；默认不启用是因为它静止不动，与正在自转的木星放在一起不合理。
    - **性能模式**：首页那颗木星要跑 HDR + bloom + MSAA + 各向异性一整条后处理链。进站时会**检测一次**并自动选档：
      - 判据主项是 **GPU 时间**（`EXT_disjoint_timer_query_webgl2` 采 32 帧取中位；中位 > 17ms 或 p75 > 34ms 判为低配），而不是帧率 —— 帧率会被 vsync 钉在 60，分不出"刚好卡"和"很吃力"。拿不到该扩展时回退到帧间隔判据，并在 `__spaceGlobe.perfMode()` 的 `detectedBy` 里如实标出用的是哪一种。软件渲染器（SwiftShader/llvmpipe）、≤2 核、`deviceMemory ≤ 2` 走快通道直接判低配。
      - **低配档**：关闭后处理与 bloom、MSAA 4→2、各向异性降到 2、木星贴图用 2048 档（省 545KB 下载与相应显存）；锐化保留（它只是合成里的几次采样，砍掉只损观感不省性能）。
      - 判定结果存 `localStorage`（键 `leafmytop:space-perf-mode`），**第二次进站不再检测、也不重复提示**；导航栏「关于」右侧有切换按钮，切到低配会重载以真正换掉贴图档位。
      - 排障入口：`?perf=high|low` 强制档位、`?perfsamples=<n>` 指定采样帧数、`?toastms=<ms>` 改变提示条时长、`?perftest=1|quiet` 打印/静默检测结果。注意 **URL 是一次性覆盖**：只要 `localStorage` 已有档位，就以存储为准（否则切换按钮点完重载会被 URL 拽回去）。
    - **真实的部分**：相位、光照方向、自转轴取向、相对大小次序、画面次序、恒星位置与亮度、银河走向，全部来自真实天文数据（详见 `source/custom/effects/space-system.js` 与 `space-globe.js` 的文件头）。
    - **木星的"细节还原"**：木星贴图的源本身就是软焦（磁盘上的 4096×2048 原图与现用的 3072/2048 档，在**同一块物理区域**上量出的高频是同量级 1.56 / 1.16 / 1.89，说明源里没有更多细节可挖；采样率也已到 3072 在球心处 ≈0.97 纹素/屏幕像素的极限）。因此在最终成像里加了一步 unsharp mask（`space-globe.js` 的 `SHARPEN`，线性 HDR 域、色调映射之前，默认量 0.20 / 半径 2.0，`?sharpen=0` 可关）。它本质是**反卷积**——把"原始信号更锐、只是被光学与重采样糊过"这个假设反推出来，因此**放大了源里并不确定的成分**。这一项只作用于最终成像，不参与任何"真实数据"类断言。
